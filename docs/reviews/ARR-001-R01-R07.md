**R01–R07 decisions have been accepted.** A limited validation-only Phase 0 is now *specifiable* without paid API access, purchases or actual market-data ingestion. ## Phase 0 start gates (NOT proof of production readiness)

**START-01 — Explicit work authorization:** Obtain separate user approval to *execute* scoped Phase 0. This ARR itself only documents the plan. Work should occur through reviewable commits/PRs with no secrets.
**START-02 — Repository & safe mode:** Confirm branch rules and read-only inspection first, preserve current main and validate static catalogs. Offline mocks by default; no broker order APIs, no paid AI, no market-data ingestion without dataset-specific rights.
**START-03 — Hardware access & safety consent:** Actual Mac model, OS build, FileVault status, power setting and existing backup/UPS inventory require physical/user access. Read-only inventory may proceed, but changes to disk unlock, system LaunchDaemons, power or recovery tests require separate explicit approval and rollback plan.
**START-04 — Licensing safe path:** Mock/fixture tests can begin without live provider data. Any external historical sample requires a recorded data-specific license decision prior to retrieval/storage/analysis.
**START-05 — Cost guard:** No procurement, cloud storage setup or billable external inference. R07-03 must remain zero monthly/daily/call.

**Start recommendation:** `CONDITIONAL_GO_FOR_PHASE0_SPEC_AND_MOCK_SPIKES` after explicit approval; **NO-GO for unattended host modification or real-data collection** until respective access/security/rights are confirmed.

## Critical blockers to Phase 0 validation completion / production

### B-01 — FileVault vs. zero-login unattended recovery (CRITICAL)
Apple documents that FileVault protects data with a credential unlock at boot; SSH unlock in newer macOS is remote operator action, **not zero-person automatic unlock**. Even if Mac mini can auto-power and LaunchDaemons can run pre-login, protected data may remain inaccessible. Prove approved end-to-end solution with security review; do NOT silently disable FileVault, store unlock passwords on same host, enable GUI auto-login or weaken disk controls. Fallback choices: prove safe managed key/unlock process, native macOS daemon with approved security, or independent supported Linux hardware — all require tests and owner decisions.

### B-02 — Pre-login VM service feasibility (HIGH)
Need a pinned, supportable headless ARM64 VM runtime, system-level startup, storage access, networking, power failure recovery, systemd/Docker lifecycle and app health with **no logged-in user**. Docker Desktop's start-on-login is not evidence. Test >=3 cold boots / actual power restoration; core health target <=10 min after host/network ready (target, not achieved).

### B-03 — Existing backup hardware and offsite recoverability (HIGH)
R07-04 means **zero new purchase budget**, not verified equipment. Inventory actual existing NAS/SSD/HDD/UPS and backup keys, health, capacity, offsite cost and data entitlement. Test encrypted *independent* backup and clean-target restore. RPO <=24h and RTO <=8h only if demonstrated. Missing UPS is an explicit residual risk; it does not automatically authorize purchase.

### B-04 — Market data rights and historical completeness (HIGH)
All R04 10+14 data entries remain PENDING; no ten-year history is downloaded or licensed yet. Dataset-specific operations (download/retention/backtest/external inference/training/backups) must default DENY. Licenses and required PIT revision evidence may be unavailable. Phase 0 tests mocks first; compare official/third-party endpoints only with granted rights. Document measured missing dates and 7 eligible vs 3 late-listed.

### B-05 — OpenBB V5 runtime / architecture dependency (MEDIUM-HIGH)
OpenBB only conditionally adopted. Prove Python/REST/MCP + chosen provider extension on Linux ARM64 within 16GB guest allowance; compare native TWSE adapter and extension overhead; isolate ingestion model from SDK. Fallback native connectors for TW.

### B-06 — Time correctness and backtest invariants (HIGH)
Trading-day/source publication timestamps and revisions not proven. Build offline fixtures for R05 delay/correction, as-of joins, post-close decision/next session fill, split/dividend, futures night-session mapping, daily-reset leveraged/inverse ETFs. Use no invented official SLAs and never backdate first_seen.

### B-07 — Zero-cost AI and private endpoint security (HIGH)
NT$0 monthly/daily/per call OpenAI; all external paid AI denied including retries and alternative vendor fallback. Mock-only research labeled. No credentials in GitHub or logs. Private Tailscale/no public database; verify configuration in mock/deployment.

### B-08 — Operations, monitoring and PR evidence (MEDIUM)
No observed GitHub Actions PASS reported yet; static read-back is not CI execution. Monitoring, offsite heartbeat, missed-session catch-up and real restore drill need demonstrated logs. Permissioned, auditable branch/PR process is required before substantive implementation.
